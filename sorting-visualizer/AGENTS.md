# 排序實驗室｜專案協作規則

## 專案目標

用繁體中文和可逐步操作的長條圖，幫助第一次學排序的讀者理解比較、交換和定位。使用者能用同一組資料重跑不同演算法，並區分一次執行的操作統計與漸近複雜度。

## 檔案結構

| 位置 | 用途 |
| --- | --- |
| `docs/index.html` | 操作區、圖例、步驟說明與演算法筆記 |
| `docs/assets/algorithms.js` | 演算法清單、教學資料、事件生成及時間軸 |
| `docs/assets/app.js` | 讀取演算法清單、更新畫面、操作與播放 |
| `docs/assets/site.css` | 網站排版、色彩、長條圖和手機版樣式 |
| `docs/.nojekyll` | 讓 GitHub Pages 原樣發布靜態檔案 |

- 用原生 HTML、CSS、JavaScript。腳本依 HTML 裡的順序載入，支援直接開啟 `docs/index.html`，以及 GitHub Pages 儲存庫子路徑。
- 使用 UTF-8、`zh-Hant`、小寫英文字與連字號檔名，站內連結與資源使用相對路徑。
- 保留淺紫工作區、白底面板與有色長條圖。比較、交換、已定位三種狀態都提供文字圖例及當前動作說明。控制元件需支援鍵盤並保留可見焦點。

## 新增演算法

1. 在 `docs/assets/algorithms.js` 實作生成器 `function* sortName(values)`。演算法只接觸傳入的工作陣列，介面、計時器和隨機資料由 `app.js` 管理。
2. 使用零起始索引。每次比較兩個資料值前送出 `compare(left, right)`。交換則用 `yield* swap(values, left, right)`，會更新該陣列並送出事件。若需要直接寫回，更新後送出 `{ type: "write", indices: [index] }`。只有位置確定為最終順序時，才送出 `settle(index)`。
3. 在 `sortingAlgorithms` 新增一筆資料，填寫唯一的 `id`、中英文名稱、一段運作概念、比較策略、最佳／平均／最差時間、額外空間、穩定性及目前版本的限制，最後指定 `steps`。下拉選單和筆記面板都會從這份清單讀取。
4. 確認同一組輸入的每個步驟都能重播和倒回，且演算法不改動傳入 `buildTimeline()` 的原始陣列。時間軸會在生成器結束後加入完成畫面。
5. 用已排序、反序、含重複值、單一元素與空陣列驗證最終順序。核對計數，並在瀏覽器試跑播放、暫停、單步、倒回、重設及更換演算法。以約 390 像素寬度檢查操作區。

## 統計與內容

- 比較次數只計資料值的比較。每次交換記兩次陣列寫入，每次單位置寫回記一次。跨演算法採相同定義。
- 複雜度資料描述本站實作；額外空間以演算法工作空間為準。視覺化用的事件、時間軸與快照不納入演算法成本。
- 更換演算法和重設都保留原始資料。只有「洗牌」與改變資料筆數會建立新資料，方便在相同輸入下觀察。
